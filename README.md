## traffic-violations

Сервис для анализа нарушений ПДД на Go.

Проект обрабатывает события проезда транспортных средств, определяет факт проезда на красный сигнал светофора и сохраняет информацию о нарушении во внешнее хранилище.

##### Задача

Реализовать сервис потоковой обработки событий.

Сервис получает сообщения из брокера `cat`, анализирует данные о проезде транспортного средства и при наличии нарушения сохраняет результат в хранилище `dog`.

В рамках проекта нарушением считается только проезд на красный свет.

##### Описание

При запуске приложение инициализирует конфигурацию, подключается к брокеру сообщений и внешнему хранилищу.

Брокер возвращает канал, в который поступают сообщения.

Сообщение — это JSON-представление объекта `Passage`.

`Passage` содержит государственный номер автомобиля `LicenseNum` и набор точек движения `Track`.

Каждая точка содержит Unix timestamp в секундах.

Светофор работает по следующему правилу:

- с `0` по `44` секунду каждой минуты включительно — зелёный сигнал;
- с `45` по `59` секунду каждой минуты включительно — красный сигнал.

Анализируется только последняя по времени точка маршрута, так как именно она считается точкой пересечения линии светофора.

Если последняя точка попадает на красный сигнал, сервис сохраняет нарушение в хранилище.

##### Архитектура

Проект разделён на слои:

- `cmd/app` — точка входа в приложение;
- `internal/config` — конфигурация;
- `internal/service` — бизнес-логика;
- `internal/ports` — интерфейсы внешних зависимостей;
- `internal/adapters` — адаптеры брокера и хранилища;
- `models` — модели данных.

Бизнес-логика зависит от интерфейсов, а не от конкретных реализаций `cat` и `dog`.

Это позволяет заменить брокер или хранилище с минимальными изменениями в коде.

##### Особенности реализации

- конкурентная обработка сообщений;
- worker pool;
- graceful shutdown;
- retry при сохранении данных;
- обработка некорректных сообщений;
- разделение бизнес-логики и инфраструктурного кода.
